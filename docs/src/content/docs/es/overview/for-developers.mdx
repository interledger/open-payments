:::tip[Resumen]
Desarrollar con Open Payments implica escribir un cliente que llame a las API de Open Payments para configurar pagos entre cuentas compatibles con Open Payments. Las propias cuentas y los servidores que las exponen son operados por entidades que administran cuentas (ASE).
:::

Esta página es el punto de partida para los desarrolladores que crean aplicaciones, servicios u otro software que consumen las API de Open Payments.

## Lo que desarrollará

Un cliente en Open Payments es un software que:

- Descubre una cuenta compatible con Open Payments a partir de la [wallet address](/es/concepts/wallet-addresses/) que identifica la cuenta.
- Solicita [concesiones](/es/identity/grants/) al servidor de autorización de la cuenta.
- Crea recursos `incoming-payment`, `quote` y `outgoing-payment` para configurar un pago.
- Firma cada solicitud con una clave que el servidor de autorización puede verificar.
- Gestiona los flujos de consentimiento interactivos.

Un cliente nunca mueve dinero. Las ASE de cada lado del pago son responsables de la liquidación.

## Qué se excluye intencionalmente de la ruta para desarrolladores

Parte de la documentación de Open Payments describe las responsabilidades de la ASE, no del cliente. Esto incluye cómo está estructurado el wallet address server, cómo el servidor de autorización procesa las concesiones, cómo el servidor de recursos transfiere los pagos a la liquidación y cómo se integra el proveedor de identidad. Esas páginas se encuentran en la sección [Para las ASE](/es/implement/ase-overview/) y están dirigidas a los ingenieros que implementan la pila de servidores.

Si al leer una página para las ASE se pregunta si debe implementar algo del lado del cliente, la respuesta casi siempre es no.
