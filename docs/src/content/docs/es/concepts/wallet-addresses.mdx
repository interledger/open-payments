:::tip[Resumen]
Una wallet address es un identificador seguro de una cuenta compatible con Open Payments (estándar de pagos abiertos), que se puede compartir. Cada wallet address funciona como un punto final de servicio dentro de las interfaces de programación de aplicaciones (application programming interfaces, API) y permite que los clientes interactúen con la cuenta subyacente.
:::

En el centro de todas las interacciones de Open Payments, se encuentra una cuenta compatible con Open Payments. Cada cuenta compatible con Open Payments se identifica por medio de una URL o más. Estas URL no solo son identificadores de cuentas, sino también puntos finales de servicio para obtener acceso a las API de Open Payments. Estas URL se denominan **wallet addresses**. No todas las URL son wallet addresses, pero todas las wallet addresses son URL.

## ¿Qué hace que una URL sea una wallet address?

Una URL solo es una wallet address si cumple con los siguientes criterios:

- El servidor que gestiona las solicitudes HTTP admite el protocolo de Open Payments.
- La URL utiliza el protocolo `https` y no tiene componentes de `user-info`, `port`, `query string` ni `fragment`.

### Cómo verificar una wallet address

La forma más rápida de comprobar que una URL es una wallet address es haciendo una solicitud HTTP `GET` a la URL con un encabezado `Accept` con el valor `application/json`.

```http
curl --request GET \
 	--url https://wallet.example.com/alice \
 	--header 'accept: application/json'
```

Si la URL es una wallet address, en la respuesta, se proporcionarán datos sobre la cuenta compatible con Open Payments subyacente, lo que incluye la URL del punto final de la solicitud de concesión de autorización (el `authServer`). El punto final de la solicitud de concesión de autorización se utiliza para obtener tókenes de acceso para conectarse a la cuenta por medio de las API de Open Payments.

```http
HTTP/1.1 200 Success
Content-Type: application/json

{
  "id": "https://wallet.example.com/alice",
  "publicName": "Alice",
  "assetCode": "USD",
  "assetScale": 2,
  "authServer": "https://auth.wallet.example.com"
}
```

## Wallet address server

Al configurar un pago, el cliente debe obtener la wallet address tanto del remitente como del destinatario. Dado que el remitente, por lo general, es el usuario del cliente, el cliente puede obtener su wallet address, por ejemplo, durante el proceso de incorporación. La entidad que administra la cuenta (account servicing entity, ASE) debe autenticar al remitente para concederle el permiso que necesita para acceder a su cuenta compatible con Open Payments.

Un wallet address server es el punto final de una API que recupera información pública sobre una wallet address, lo que incluye sus claves públicas asociadas. Para obtener más información técnica, visite los [documentos de la wallet address server API](/es/apis/wallet-address-server/operations/get-wallet-address/).

## Privacidad y seguridad

Una wallet address funciona como un identificador proxy (alias) de una cuenta financiera subyacente. Si una ASE lo permite, una sola cuenta puede tener múltiples wallet addresses. Permitir que los titulares de cuentas generen wallet addresses únicas para cada cliente con el que interactúan puede ayudar a prevenir que una sola dirección se convierta en un vector de rastreo.

En última instancia, definir la configuración admitida para la relación entre las wallet addresses y las cuentas del usuario queda a criterio de la ASE. Este acoplamiento flexible permite que las wallet addresses se desactiven o, incluso, que se vinculen a una nueva cuenta (aunque deben tenerse en cuenta algunos aspectos antes de permitirlo) sin afectar a la cuenta subyacente.

Para cualquier cliente, una wallet address sirve tanto como una cuenta. Los clientes deben tratar a dos wallet addresses diferentes como si fueran cuentas distintas, incluso aunque sepan que son proxies de la misma cuenta subyacente. El permiso para que un cliente acceda a una cuenta por medio de una wallet address no se concede de forma automática al acceder a la misma cuenta a través de otra wallet address.

## Descubrimiento e interacción

El uso de las URL como instrumentos de pago resuelve dos de los problemas más grandes de la experiencia de usuario (UX) en los pagos actuales: la facilidad de descubrimiento y la interacción.

Las URL (localizadores de recursos universales) se han utilizado en Internet durante décadas para permitir que los clientes localicen un recurso de forma directa y comiencen a interactuar con él por medio de HTTP. Una wallet address es un identificador proxy y un localizador de recursos para la cuenta subyacente, que se utiliza para acceder a la cuenta por medio de las API de Open Payments y comenzar a interactuar con la ASE de la cuenta.

Además, es preferible utilizar las URL a modo de proxies antes de sobrecargar a otros identificadores, como las direcciones de correo electrónico y los Números Internacionales de Directorio de Suscriptores de Estación Móvil (Mobile Station International Subscriber Directory Numbers, MSISDN), dado que estos proxies no tienen un estándar para la interacción. Por lo tanto, los identificadores como un MSISDN o un correo electrónico requieren un registro que relacione el identificador con un proveedor de cuenta y también un mecanismo para gestionar esta relación de manera segura.
